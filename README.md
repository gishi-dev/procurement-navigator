# 調達ナビ

**仕入先を巡り、在庫・価格・納期をひとつの比較表へ。**

架空の家電メーカー「ギシ電機」の調達担当向けに作った、個人開発のデモです。
型番・必要数・希望日を指定すると、実際のブラウザが架空の仕入先10社を開き、
検索と商品詳細の確認を進めます。ブラウザ画面と比較結果を並べて見られます。

会社・人物・商品・仕入先・取引条件はすべて架空です。実運用・納品の実績ではありません。
購入・注文・メール送信の機能はありません。

![調達ナビの比較画面](images/comparison.png)

## 試せること

- 冷却ファン・温度センサーの型番検索と、在庫・単価・納期・送料の収集
- 送料を含む税別総額と到着目安の比較
- 在庫不足・希望日超過の区別と、条件に合う最安候補の表示
- 候補ごとの選定理由、元の商品ページと操作履歴の確認、調査途中の停止

初期条件は冷却ファン20個・7日後まで。最安の単価を持つ仕入先は納期に間に合わず、
条件を満たす仕入先の中から候補を示す例になっています。
在庫・納期を満たしていても、最安候補より総額が高い仕入先には差額を表示します。
必要数を100個にすると、すべての仕入先が在庫不足になる例を試せます。

## 実際の業務で使うイメージ

想定する利用者は、製造業の購買・調達担当者です。例えば、生産予定を確認して
「温度センサーが20個足りない。来週までに揃えたい」と分かった場面で使います。
以下は実業務へ導入する場合の想定で、実際の導入実績ではありません。

1. **必要な部品と条件を決める。** 担当者が型番・必要数・必要な日を指定します。
2. **登録済みの仕入先を調べる。** 事前に登録・承認したサイトの一覧を巡り、検索と商品詳細の確認を進め、価格・在庫・納期・送料を集めます。
3. **同じ条件で比較する。** 必要数を確保でき、希望日に間に合う候補を総額で比較します。各社の元ページと、候補から外れた理由も確認します。
4. **担当者が発注先を決める。** 取引実績、品質、保証、実際の納品日の確認などを踏まえて選び、既存の購買手続きで発注します。

### 仕入先のサイトは事前に登録する

実業務では、調査してよい仕入先のサイトをあらかじめ一覧に登録し、その範囲で調べる想定です。
例えば、既存の取引先台帳をもとに、仕入先名・サイトURL・検索ページ・ログインの必要性・
許可された操作範囲を整理します。新しい取引先を調べる場合も、対象サイトを確認してから一覧へ追加します。

URLを登録するだけで、どのサイトでも動くわけではありません。サイトごとに検索方法や
価格・在庫・納期の表示が異なるため、操作と読み取りへの対応、動作確認が必要です。
一覧を管理する機能と、登録したサイトを正しく調べるための対応は、両方を用意します。

現在のデモは、架空の10社をあらかじめ登録した状態です。仕入先の追加・編集用の管理画面や、
実際の取引先台帳との連携は含みません。実業務向けには、管理画面や台帳で一覧を管理する形を想定しています。

### 比較結果をどう使うか

このデモの温度センサー20個の例では、北星パーツが34,200円・2日後、
光洋サプライが32,300円・5日後です。希望日が7日後なら、両社が条件を満たし、
総額が1,900円安い光洋サプライを候補として示します。
希望日を2日後に変えると、光洋サプライは納期の条件から外れ、北星パーツが最安候補になります。

おすすめの基準は「在庫と納期を満たす候補の中で、送料込み総額が最安」です。
品質や取引実績まで評価した結果ではありません。担当者は元ページを確認し、
社内の取引条件に照らして、おすすめ以外の仕入先を選ぶこともできます。

減らしたい作業は、サイトごとの検索、条件の転記、比較表づくりです。
実際の削減時間はまだ計測していません。導入時には、同じ部品・仕入先で手作業と比べて
調査時間と読み取りの正確さを確認し、効果を判断します。

### 実サイトへ導入する際の追加対応

今のデモは、このアプリ内の架空サイトだけを調べます。実際の仕入先で使うには、
次の対応が必要です。

- 対象サイトの利用条件と操作範囲の確認、検索・商品詳細画面への対応、必要なログインの管理
- 税込・税別、数量による単価、送料、納期表現、同じ型番かどうかの確認をそろえる処理
- 読み取れない条件や見積依頼が必要な商品を、推測せず担当者の確認へ回す流れ
- 比較結果の保存、必要に応じた既存の購買台帳・承認手続きとの連携
- 外部AIへ送ってよい商品情報・取引条件の確認と、送信する情報の制限

実業務でも、候補の提示と発注操作は分けて扱います。この公開デモには、
実サイト対応、取引先への問い合わせ、発注、承認手続きとの連携は実装していません。

## AIとコード、人の分担

| 担当 | 役割 |
|---|---|
| Jev | 現在の画面に存在する候補から、入力・検索・詳細表示・条件収集の次の操作を選ぶ |
| コード | 入力する型番を保持し、操作対象を限定する。表示された条件を取得し、数量・総額・日付を比較する |
| 人 | 元ページと比較結果を確認し、発注先を決める |

Jevモードでは自由な操作コードを生成させません。観測できた操作だけを選択肢として渡し、
受け取った選択肢を確認して実行します。ブラウザのアクセス先はこのデモの仕入先ページに限定します。
同時に複数の調査を開始できないようにし、API障害を実演モードへの自動切り替えで隠しません。
1社あたりの操作回数には上限があります。条件を取得できなかった仕入先は未確認として残します。

### 2つの実行モード

- **ブラウザ実演**：APIキー不要。次の操作は固定ルールで決め、実際のChromiumで検索・確認します。
  Jevの性能を示すものではありません。
- **Jevで判断**：TypeSafe APIに架空の型番とページ本文を送り、Jevが次の操作を選びます。
  APIキーと利用料金が必要です。文字・判断用のモデルであり、画像は送信しません。

Jev `jev-1.13.0` で、温度センサー20個・7日後までの条件を実際に確認しました。
10社の検索・詳細確認・条件収集を40操作で完了し、在庫と希望日を満たす最安候補を表示しました。
北星パーツには、最安候補より総額が1,900円高い理由が表示されます。
この結果は、このデモ内の架空サイトでの確認です。一般のサイトでの精度・速度・料金を保証するものではありません。
ブラウザ実演モードの結果を、Jevの精度や速度として扱わないでください。

## 起動

Python 3.13以上を使用します。

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install .
playwright install chromium
uvicorn app:app --host 127.0.0.1 --port 8871
```

ブラウザで `http://127.0.0.1:8871` を開きます。
Jevを使う場合は、起動前に `TYPESAFE_API_KEY` を環境変数へ設定してください。
キーをソース・画面・履歴へ書き込まないでください。`.env` は自動では読み込みません。
既定のモデルは `jev-1.13.0` です。`JEV_MODEL` で変更できます。
ポートを変える場合は、`PORT` 環境変数と起動時の `--port` を一致させます。

## デモの範囲

実際の仕入先サイト、ログイン、支払い、注文、サイトごとの利用規約への対応は含みません。
実演用サイトはこのアプリ内にあります。取得条件はサンプルで、納期は調査日からの目安です。
結果はメモリ内に保持し、サーバー再起動で消えます。ローカルでの単一利用を想定しています。
